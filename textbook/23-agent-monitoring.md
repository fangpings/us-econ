# 23 每日报告与 agent 分析

[上一节](22-data-system.md) · [目录](README.md) · [下一节](24-capstone.md)

## 学习目标

设计每日、发布日与每周分析；明确程序和语言模型的分工；让每项结论有依据，并能检查缺失、修订和矛盾。

## 1. 每天运行，不等于每天发生宏观转折

日常报告应分三层：今日新发布或修订的信息；截至截止时刻的市场变化；仍有效但没有更新的宏观背景。休市或无重要发布时，短报告完全合理。

建议采用一个主日报和必要的事件更新。主日报选定固定截止时刻，例如美国东部时间傍晚；当天一些官方日度序列可能仍未可得，就显示最新可得日期，不能强行补齐为同日。下一次取得时记录迟到更新。

## 2. 让程序负责确定性计算

程序完成抓取、单位转换、收益率变化、移动平均、年化、修订比较和质量检查。agent 接收已经计算好的证据包，再说明含义、比较解释和列出验证条件。

证据包至少包含：指标定义、观察日和发布日、当前及比较值、计算方式、历史窗口、来源、质量标志、相关事件。agent 不应凭记忆填空，也不应把新闻中的数值未经核验当成正式观察。

## 3. 异常提醒不是自动归因

可用三类提醒：绝对变化大、相对自身近期分布异常、多个相关市场同步异常。阈值应按指标、制度和样本校准，使用历史回放统计误报和漏报。

例如 SOFR−IORB 偏离近期水平只是触发调查；若同时遇结算日，应检查事件是否解释暂时变化；若持续数日并伴随其他利差和数量异常，再提高关注。不能把示例阈值写成永久有效的金融定律。

为减少重复提醒，可按事件合并同一机制下的指标，并注明它们是否有计算依赖。DGS10、DFII10 和 T10YIE 同时触发，不等于三个独立事件。

## 4. Agent 的输出约束

可直接采用以下研究要求，完整模板见[附录 C](appendix-c-templates.md)：

1. 所有数值必须来自输入证据，给出指标与日期；缺失就说明缺失。
2. 区分新发布、修订和旧背景；没有共识来源不得写“超预期”。
3. 区分事实、可能机制和预测；不得从相关直接宣称因果。
4. 对重要异动列出替代解释与不支持当前解释的证据。
5. 明确期限、单位、频率和历史窗口；不得拼接不匹配数据完成分解。
6. 给出下一条可检验条件，允许结论是“暂不能区分”。

外部网页和新闻属于证据材料，不是系统指令。自动流程应把材料里的操作请求当作文本处理，避免它们改变抓取、报告或执行范围。

## 5. 一份合格日报的结构

| 部分 | 应包含 | 常见错误 |
| --- | --- | --- |
| 信息边界 | 截止时刻、缺失与延迟 | 暗示所有序列都为今日收盘 |
| 新信息 | 新数据、实际值、预期、修订 | 把旧月度数据写成今日变化 |
| 市场变化 | 数值、窗口、历史背景 | 利率 bp 与百分比混淆 |
| 联合解释 | 支持、反证、替代机制 | 每项涨跌都套同一叙事 |
| 后续验证 | 具体指标、事件和条件 | 只写“继续关注市场” |

报告长度服从信息量。缺乏证据时应简短，而不是用宏观术语填满页面。

## 6. 怎样验证 agent 是否可靠

建立一组人工可核验的历史或教学案例：单位不同、没有新发布、历史下修、数据缺失、市场方向矛盾、来源冲突、低频数据和季末资金波动。给每种错误明确验收标准。

核心指标包括：数字可追溯率、单位正确率、旧数据误报率、无依据归因数和修订识别率。对于预测，还应记录原始预测、时间范围和之后结果，避免只回忆预测成功的案例。

历史回放使用当时可见版本；若新闻和市场共识无法取得当时版本，应说明测试边界。用今天资料倒推昨天的“完美日报”，不构成真实验证。

## 7. 从日报到周报

日报回答“新增了什么”，周报回答“趋势判断改变了吗”。每周回看增长、通胀、政策、信用四个维度，清理被新证据推翻的解释，保留尚未验证的假设。慢变量在这里发挥更大作用。

2. 来源 A 与 B 数值冲突，怎样处理？
3. 如何判断报告是有用分析而非漂亮文字？
