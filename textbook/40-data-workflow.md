# 40 数据工作流：指标注册、版本、转换与质量检查

[上一章](39-historical-research.md) · [目录](./) · [下一章](41-research-reports.md)


> 第 40 章，2026-10-03。配套程序只读取仓库内离线 JSON，不自动抓取、不调用模型、不发送报告。Python 3 标准库即可运行。

## 1. 自动分析首先是数据定义问题

把 GDP、CPI、SOFR 和股价都存成“日期、数值”，很快会遇到歧义：日期是经济观察日还是发布日期？GDP 是水平还是年化增速？股价是否复权？同一季度的两个 GDP 值是重复错误还是正常修订？

本章将研究流程拆成原始资料、结构化记录、版本选择、确定性计算、人工解释五层。自动化的第一目标是使错误可见，而不是每天生成更多文字。

读完应能运行本地小程序、解释输出、故意制造错误并观察拒绝，最后知道它尚未解决哪些真实数据问题。无需编程基础，先按命令运行再读代码。

## 2. 一条记录至少要描述什么？

仓库 `data/research-observations.json` 采用以下字段：

| 字段 | 含义 | 为什么不能省略 |
| --- | --- | --- |
| series | 固定口径序列标识 | 同名不同口径不可直接拼接 |
| period | 观察期 | GDP 的季度不是发布日期月份 |
| released_at | 公开发布时刻，含时区 | 防止引用未来资料 |
| retrieved_at | 本地取得或整理记账时刻 | 区分公众可得与本地实际可得 |
| vintage | 版本标签 | advance、second、third 不是三个季度 |
| unit、frequency | 单位与频率 | 指数、百分比和美元不能混算 |
| adjustment、scope | 季调/年化与覆盖 | 方法边界改变需要记录 |
| value、kind | 数值及真实/教学类别 | 不让虚构例子进入现实报告 |
| source | 原始来源 | 为人工复核保留入口 |

series 本身不能保证口径永远相同。若范围或方法产生不可直接比较的断点，应建立新序列并记录映射，而不是继续追加看似连续的数。真实项目还需季调版本、许可、源文件哈希、提取程序版本、时区精度等；本练习没有声称覆盖所有生产需求。

## 3. 从原文到记录，不是猜一个 API 名称

练习的三个真实记录来自 BEA 对 2024 Q1 的[初值](https://www.bea.gov/news/2024/gross-domestic-product-first-quarter-2024-advance-estimate)、[第二次估计](https://www.bea.gov/news/2024/gross-domestic-product-first-quarter-2024-second-estimate-and-corporate-profits)、[第三次估计](https://www.bea.gov/news/2024/gross-domestic-product-third-estimate-corporate-profits-revised-estimate-and-gdp-industry)，值依次为 1.6%、1.3%、1.4%，均是实际 GDP 季环比年化。

先人工核对表头、发布时间和频率，才录入字段。另两条 TEACH_PRICE_INDEX 为虚构指数 100 和 100.3，使用 `teaching://` 来源并标明 teaching。程序不把它们当官方数据。

资料中的 retrieved_at 统一写为 2026-10-03 UTC 00:00，是教材整理的教学记账时刻，不是每条网页访问的精确时间。它足以演示版本选择区别，但不能用于声称毫秒级系统性能。参见仓库 `data/README.md`。

## 4. 按截止时间选择版本

在仓库根目录执行：

```sh
python3 tools/research_lab.py validate
python3 tools/research_lab.py asof --at 2024-05-01T00:00:00Z
```

第一条确认五条记录通过结构校验。第二条只应返回 Q1 GDP 初值 1.6：5 月 30 日和 6 月 27 日的版本在此截止线之后，即使已经存在于今天的文件里，也不得入选。

算法依次做三件事：筛掉发布日期晚于截止线的记录；按“序列、观察期”分组；每组保留截止前发布时间最晚的一条。它不会把数值最大的版本当“最好”，也不会默认最新下载覆盖过去。

将截止时间改成 `2024-06-01T00:00:00Z`，应选 1.3；改成 `2024-07-01T00:00:00Z`，应选 1.4。这里的“最新”只指样本里当时可得的版本，不包括未收录的后续年度修订。

再执行：

```sh
python3 tools/research_lab.py asof --at 2024-07-01T00:00:00Z --availability local
```

结果为空，因为本地入库在 2026 年。public 模式重建历史公众信息集，local 模式还要求本地已取得。两者各有研究用途，混用则会产生虚假的回测表现。

## 5. 计算层只做有定义的转换

运行虚构指数比较：

```sh
python3 tools/research_lab.py compare --at 2025-04-01T00:00:00Z --series TEACH_PRICE_INDEX --earlier 2025-01 --later 2025-02
```

输出保留两条输入和计算结果：指数点数差 0.3、区间增长率约 0.3%。浮点显示可能有尾数，展示时舍入不应改变原始数据。输入序列、单位、范围、调整和真实/教学类别不一致时拒绝比较。

如果输入是两个百分比，程序给百分点差，不把它误报成百分比增长；同一观察期的不同版本必须按修订处理，不允许调用跨期增长。区间不相邻时只称区间变化，不能擅自命名月环比或同比。

工具还包含年化转单期与固定月供函数，用于测试和算例核验。年化 1.6% 转季度为 `(1+0.016)^(1/4)−1`；利率单位要分清输入是 0.06 还是 6。没有定义的“流动性总量”不应随意把几个美元余额加减后输出。

## 6. 怎样测试一条研究流程？

执行：

```sh
python3 -m unittest discover -s tests -v
```

测试不仅看正常例子，还检查截止前一秒、发布时间恰好相等、时区换算、修订、重复版本、缺失值、非有限数、口径变化和本地可得性。Python 的 bool 可被当作整数，校验也显式拒绝，防止 true 被当成数值 1。

在文件副本上尝试三种错误：把一条 value 改为 null；复制相同版本；把某 GDP scope 改成名义 GDP。程序应报错并停止，而不是静默补零或保留最后一行。不要直接破坏原始练习包；原始资料、试验副本与派生结果应分开。

通过测试不等于数据真实：错误地抄成 16 仍可能是合法数值。应有第二层人工核查或来源对照、量级异常检查、缺口与发布日期检查。公式正确也不能修复输入口径错误。

## 7. 从练习到真实工作流，还差什么？

真实采集需官方接口或下载渠道、授权和频率限制、失败重试、文件归档、解析版本、数据修订和安全配置。第三方许可允许浏览不一定允许再分发。缺失应有原因，如尚未发布、接口失败或不适用，而非统一填 0。

本程序目前只支持月度和季度记录，不处理日内行情、市场节假日、跨频率对齐、自动预期抓取或复杂口径转换。它不判断是否应该投资，也不生成自由文本分析。把这些边界说清，才不会把小型教学脚本误称生产系统。

未来接入任何分析者或 agent，都应先提供经过版本选择的输入、确定性计算、来源和缺失清单，再要求它区分事实与解释。语言生成不能自行补齐未取得的数字。

## 8. 练习与答案

### 练习一：发布日没有具体时刻

某资料只有日期，没有时刻。能否将其设为当天 00:00 放进盘前分析？

<details><summary>参考答案</summary>

不能，那会假装全天已知。应记录时间精度，采用明确保守的日终可得假设，或不参加日内研究。本工具要求精确含时区时刻，因此这类资料不能未经说明直接输入；需要扩展模型而不是捏造时间。

</details>

### 练习二：缺失与零

贷款变化缺报和确认为零，对报告有何不同？

<details><summary>参考答案</summary>

零表示在指定口径下没有净变化，缺报表示不知道。将缺报填零会制造平稳信号、污染均值和趋势。报告应保留上次值及观察期，但不能把它伪装成新发布；计算窗口缺失时说明计算不可得。

</details>

### 练习三：独立小项目

在副本中新建一个教学月度指数两期，保持定义一致，运行 validate、asof 和 compare，再写一条测试保证过早截止线不能读到后一期。

<details><summary>评价标准</summary>

明确 teaching、来源与时区；按观察期区分记录；版本选择正确；计算可手算；错误用例确实失败。只打印一条漂亮曲线而无法解释数据和版本，不算完成。

</details>
